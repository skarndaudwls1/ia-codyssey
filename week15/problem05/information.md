# 문제5 화성의 날씨 데이터를 데이터베이스에 담아라

화성 날씨 데이터(CSV)를 MySQL `mars_weather` 테이블에 적재하는 프로그램이다.
아래는 `mars_weather_summary.py` 를 **실행 흐름 순서**대로 따라가며, 어떤
함수를 어떻게 사용했는지 설명한 내용이다.

---

## 1. 상수 선언

코드에서 변하지 않는 값들은 상수로 선언했다.

- `APP_DIR` : 현재 디렉토리(이 파일이 있는 폴더)를 지정한다.
- `ENV_PATH` : MySQL 관련 중요한 데이터를 `.env` 로 만들었기 때문에, 그
  파일의 경로를 지정한다.
- `TABLE_NAME` : 과제에 명시된 `mars_weather` 로 했다.

컬럼 목록은 상수로 박지 않는다. 적재·조회할 때 DB 에 직접 물어봐서
(`SHOW COLUMNS`) 실제 구조를 그때그때 읽기 때문이다.

## 2. 환경 설정 읽기 (`.env` → `DB_CONFIG`)

`load_env(ENV_PATH)` 를 통해 먼저 `.env` 파일을 읽는다.
`load_env(path)` 함수가 `KEY=VALUE` 형식에서 중요한 값만 가져와 환경
변수에 올리고, 그 값을 `DB_CONFIG` 에 넣는다. 비밀번호 같은 민감 정보를
코드에 직접 박지 않기 위해 `.env` 로 분리한 것이다(깃에도 올리지 않는다).

## 3. 프로그램 시작과 메뉴

`if __name__ == '__main__':` 을 보면 `main()` 만 실행하도록 했다. 대신
실행 중 `Ctrl+C` 나 `Ctrl+D` 를 누르면 오류 추적(traceback) 없이 종료되도록
예외 처리를 했다.

앞서 보여준 결과창은 `print_menu()` 를 통해 나타난 것이다. 여기서
`1 · 2 · 3 · 4 · 0` 으로 수행 과제들을 나눴다.

```
===== 화성 날씨 데이터 적재 =====
1. CSV 내용 확인
2. mars_weather 테이블 생성
3. CSV 데이터를 테이블에 입력
4. 테이블 내용 조회
0. 종료
```

> 참고: 1번과 3번은 각각 `read_csv_or_warn()` 을 새로 호출해 **매번 다시
> 읽는다.** 각 메뉴가 독립적으로 동작하고(1번 없이 3번부터 눌러도 됨),
> 항상 최신 파일·다른 파일 선택을 보장하기 위함이다. 파일이 작아 다시
> 읽어도 비용이 거의 없다.

## 4. 1번 — CSV 내용 확인

1번을 수행하면 `read_csv_or_warn()` 함수를 사용한다. 이 함수가
연계적으로 `choose_csv_file()` 와 `find_csv_files()` 를 진행한다.

- `find_csv_files()` : 현재 폴더에서 확장자가 `.csv` 인 파일을 모두 찾는다
  (대소문자 무관).
- `choose_csv_file()` : 찾은 파일을 번호 메뉴로 보여주고 사용자가 직접
  고르게 한다(0 은 취소). 파일이 없으면 `None`.
- `read_csv_file()` : 고른 파일을 열어, 필드명과 컬럼 내용을 **헤더와 row
  로 나눠 리스트로 저장**한다. 여기서는 타입 변환을 하지 않고 문자열
  그대로 읽는다(검증은 적재 단계에서 DB 구조와 함께 한다).

그리고 `print_csv_content()` 를 통해 CSV 파일 안의 내용을 전부 확인할 수
있다. 파일이 없다면 `None` 으로 나타낸다.

> 참고: 행이 많을 때 `print` 로 전부 호출하면 성능이 느리기 때문에,
> 파이썬의 `join`(문자열을 이어 붙이는 기능, SQL 의 JOIN 과 무관)으로 모든
> 줄을 하나로 합친 뒤 `print` 를 한 번만 호출한다.

## 5. 2번 — 테이블 생성과 DB 연결

원래 과제는 MySQL Workbench 로 테이블을 만들라고 했지만, 수행 과제를
하나하나 다 보여주기 위해 프로그램이 직접 제어하도록 했다.

2번을 누르면 `run_with_db()` 함수를 사용해 DB 와 실제로 연결한다. 연결은
보너스 과제인 `MySQLHelper` 클래스를 만들어 쉽게 할 수 있도록 했다(`with`
문과 함께 쓰면 블록을 빠져나갈 때 연결이 자동으로 닫힌다).
`run_with_db(action)` 의 `action` 에는 `create_table`(테이블 생성),
`insert_weathers`(데이터 입력) 등이 들어간다.

그 안에서 다음 예외 상황들을 미리 처리했다.

- ① MySQL 드라이버가 없을 때
- ② 외부 라이브러리(pymysql / mysql-connector)가 둘 다 없을 때
- ③ `.env` 의 DB 접속 정보가 비어 있을 때
- ④ DB·테이블 접속/작업 자체가 실패했을 때(권한, 미존재 등)

`create_table()` 은 `mars_weather` 테이블을 만든다. 이 DDL 은 `schema.sql`
의 정의와 같게 맞춰 두었다.

## 6. 3번 — CSV 데이터를 테이블에 입력

`insert_weathers(db, header, rows)` 함수를 사용해 CSV 안의 내용을 INSERT
쿼리로 변환해서 실행한다. 단, **테이블 구조(필드)를 기준으로 맞아야 들어
가도록** 처리했고, 맞지 않으면 데이터를 넣지 못하는 방향으로 진행했다.
만약 기존에 데이터가 있다면, 데이터를 비우고 새로 넣는 방향으로 진행했다.

처리 순서는 다음과 같다.

### (1) 실제 테이블 구조 읽기 — `get_table_columns(db)`

`SHOW COLUMNS FROM mars_weather` 결과(컬럼당 한 행, 6칸)에서 필요한 3가지
만 추려 `[(이름, 타입, 자동증가여부), ...]` 형태로 돌려준다.

```
[('weather_id', 'int', True),      # 자동증가(AUTO_INCREMENT)
 ('mars_date', 'datetime', False),
 ('temp', 'int', False),
 ('storm', 'int', False)]
```

자동증가 컬럼(`weather_id`)은 DB 가 알아서 채우므로 INSERT 대상에서
제외한다.

### (2) CSV 가 구조에 맞는지 판단 (위치 기준)

CSV 컬럼 수를 보고 어떻게 매핑할지 정한다.

- CSV 컬럼 수 == 테이블 전체 컬럼 수 → 자동증가 컬럼 자리는 건너뛴다.
  (과제의 실제 CSV 가 이 경우: `weather_id` 까지 4칸)
- CSV 컬럼 수 == 자동증가 제외 컬럼 수 → 그대로 매핑한다.
- 둘 다 아니면 → "CSV 구조가 테이블과 맞지 않아 반영할 수 없습니다" 안내
  후 돌아간다.

이름이 아니라 **위치 + 타입**으로 맞추므로, 헤더의 `stom`(storm 의 오타)
처럼 이름이 달라도 그대로 적재된다.

### (3) 값 ↔ 타입 검증 — `convert_value(col_type, raw)`

각 값을 해당 컬럼의 **타입**에 맞춰 변환해 본다.

- 정수 계열(`INT`): 숫자여야 한다. 소수 값은 `round()` 로 반올림한다
  (예: `21.4 → 21`).
- 실수 계열(`FLOAT`/`DOUBLE`/`DECIMAL`): 실수여야 한다.
- 날짜 계열(`DATETIME`/`DATE`): `YYYY-MM-DD` 형식의 **실제 존재하는
  날짜**여야 한다.
- 문자열 계열(`VARCHAR`/`TEXT`): 그대로 사용한다.

날짜 검증은 `is_valid_mars_date()` 가 맡고, 2월 일수를 위해
`_is_leap_year()`(윤년 판단)를 사용한다. 그래서 `2050-02-31`(존재하지 않는
날짜)이나 평년의 `2-29` 는 걸러진다.

> 왜 직접 검증하나? 존재하지 않는 날짜를 그냥 넣으면 MySQL 의 DATETIME 이
> `Incorrect datetime value` 에러를 내며 INSERT 를 거부한다. 그 난해한 DB
> 에러를 사용자가 만나기 전에, 파이썬에서 먼저 걸러 "몇 번 줄이 왜
> 문제인지" 친절히 알려주려는 것이다.

### (4) 전체 반영 방식(all-or-nothing)

한 행이라도 타입에 맞지 않으면, 일부만 넣지 않고 **그 파일 전체를 반영하지
않는다.** 어떤 줄이 왜 문제인지 안내한 뒤 돌아간다(부분 적재로 데이터가
어긋나는 것을 막기 위함).

### (5) 비우고 새로 넣기

문제가 없으면 `TRUNCATE` 로 기존 데이터를 모두 비운 뒤, `execute_many` 로
변환된 행을 한 번에 입력한다. 같은 CSV 를 다시 넣으면 행 수가 똑같아
보이므로, "기존 N개를 비우고 M개를 새로 입력" 처럼 전/후 행 수를 함께
보여준다.

## 7. 4번 — 테이블 내용 조회

마지막으로 4번을 누르면 `run_with_db(show_table)` 가 실행된다.
`show_table()` 은 `get_table_columns()` 로 실제 구조를 읽어 모든 컬럼을
조회한 뒤, `format_table()` 함수로 **실제 DB 테이블처럼 보이도록** 칸을
맞춰 출력한다(컬럼 폭 자동 계산 + 테두리 + 정렬).

```
+------------+---------------------+------+-------+
| weather_id | mars_date           | temp | storm |
+------------+---------------------+------+-------+
| 1          | 2050-01-01 00:00:00 | 21   | 56    |
+------------+---------------------+------+-------+
```
